# 隐私、运营商网络与受限网络环境说明

> 本文说明 Smart Gateway 能提供的真实隐私与网络稳定性收益、参与方仍可观察的信息，以及在运营商网络和受限网络环境中的能力边界。本文不构成对任何地区网络可达性、规避检测或持续可用性的承诺。用户应遵守所在地法律、服务条款和网络管理规定。

## 1. 威胁模型

产品主要处理以下风险：

- 公共 Wi-Fi、家庭上游或接入运营商观察明文 DNS、业务内容和目标连接；
- UDP 链路的随机丢包、乱序、抖动、MTU 黑洞和突发排队；
- 单一出口质量下降或故障；
- 多用户凭据共享造成的串流、越权和无法单独撤销；
- 配置修改、规则更新和升级造成服务不可恢复；
- 日志、诊断包和部署文件泄露长期密钥。

产品不试图解决：终端已被控制、浏览器或账号主动上报定位、应用层指纹、恶意服务器、多个基础设施运营方串通、全球级流量关联分析，以及用户主动披露身份。

## 2. 当前单跳模式的隐私边界

```text
设备 -> 加密 TUIC/FEC 隧道 -> 自托管服务器 -> WARP/Direct -> 目标服务
```

| 参与方 | 通常能看到 | 通常不能直接看到 |
|---|---|---|
| 本地网络/接入运营商 | 用户连接服务器的 IP、端口、时间、流量大小与方向 | TLS/QUIC 内业务内容；经正确配置后的 DNS 查询内容 |
| Smart Gateway 服务器 | 用户来源、设备身份、连接时序、为路由所需的目标元数据 | HTTPS 加密后的页面正文和应用载荷 |
| WARP/上游出口 | 服务器来源、目标地址、时序和流量形态 | 用户家庭真实 IP；端到端 TLS 加密内容 |
| DNS 解析器 | 查询名称、查询时间和来自代理侧的来源 | 用户家庭真实 IP（取决于 DNS 路径和代理设计） |
| 目标网站 | 出口 IP、TLS/HTTP 指纹、账号与 Cookie | 用户家庭公网 IP（代理无泄漏时） |

因此，单跳模式是加密代理，不是匿名网络。自托管服务器可能同时关联“谁在使用”和“访问了哪个目标”。

## 3. 面向运营商网络的真实优势

### 3.1 传输机密性

TUIC/QUIC 及 HTTPS 可以保护应用内容，远程 DoH/DoT 可减少明文 DNS 暴露。接入运营商仍能看到服务器地址、传输协议特征、连接时间、包长与流量方向。

### 3.2 弱网恢复

Smart FEC 可在冗余范围内恢复部分随机丢失的数据片，降低等待上层重传造成的延迟。它更适合有限随机丢包，不能恢复超过冗余能力的持续断网，也会消耗额外带宽。

第一版规划的 PMTU、pacing、GRO/GSO 和队列观测可减少分片、缓冲膨胀、系统调用和软中断开销。收益依赖线路、内核、虚拟化和网卡，必须用基线测试验证，不能用统一参数保证。

### 3.3 多出口容错

TCP 新连接可以分配到多个健康 WARP 出口；单个出口失败时新连接可尝试其他出口。UDP 会话固定到稳定出口，避免同一会话因出口变化而失效。

多出口不会叠加突破服务端公网带宽，也不是把同一业务请求复制三份。已建立连接通常不能无损迁移，出口整体故障仍会中断业务。

### 3.4 运营商特定限制

- UDP 被完全阻断时，TUIC/FEC 无法仅靠冗余恢复；产品需要另行设计 TCP/HTTPS 回退。
- 严重限速、按协议 QoS 或高峰拥塞可能使额外 FEC 反而增加排队。
- CGNAT、NAT 超时和移动网络重绑定需要会话恢复机制；当前版本能力有限。
- IPv4 与 IPv6 可能经过不同策略和 MTU，必须分别检测。
- DNS 加密不等于所有域名信息都不可见；目标 IP、TLS 元数据和应用行为仍可能泄露关联信息。

## 4. 面向受限网络和 GFW 类环境的真实优势

在存在协议识别、地址封锁、主动干预或链路质量波动的网络中，产品可能提供以下工程收益：

- 加密传输降低业务内容和明文 DNS 被被动读取的机会；
- UDP/443 与成熟 QUIC 栈具备较好的网络兼容性；
- FEC 对有限随机丢包和部分干扰有恢复能力；
- 多出口健康池减少单个上游出口故障的影响；
- MASQUE 的标准 HTTP/3 语义未来可提供另一种标准化承载和受控回退路径；
- 原子配置、健康检测与回滚能缩短异常配置带来的不可用时间。

但必须明确限制：

- 加密协议仍可能通过 IP、端口、握手、包长、时序和流量模式被分类；
- 使用 UDP/443 不代表流量与普通浏览器 HTTP/3 无法区分；
- MASQUE 是代理框架，不是不可识别或不可封锁协议；
- FEC 只能恢复丢失数据，不能绕过地址封锁、连接重置、持续丢弃或服务端不可达；
- 多 WARP 共享基础设施可能具有相关故障，不能等同三家独立运营商；
- 地址、域名或协议策略可以随时间变化，任何方案都无法保证永久可用；
- 过度填充、随机化或请求复制会增加带宽与可识别异常，不应默认使用；
- 产品不得宣传“无法检测”“永不封锁”“零丢包”或“必然可访问”。

产品工程目标应描述为“减少被动信息暴露、改善有限弱网损耗、提供可验证的多路径容错”，而不是绕过保证。

## 5. DNS 隐私：DoH、DoT、DoQ 与 ODoH

| 方式 | 提供什么 | 不提供什么 | 产品定位 |
|---|---|---|---|
| DoH | HTTPS 内的 DNS 加密，通常易于通过现有代理承载 | 解析器仍能看到查询 | 默认主上游 |
| DoT | TLS 内的 DNS 加密 | 解析器仍能看到查询；专用端口可能受限 | 默认备用 |
| DoQ | QUIC 内的 DNS 加密、独立 stream | 不隐藏查询于解析器；不天然更匿名 | 实验，默认关闭 |
| ODoH | 代理看到来源、目标解析器看到查询，降低单点关联 | 不能抵抗代理与目标串通；增加复杂度和延迟 | 后续高隐私模式 |

DoQ 的主要差异是传输行为，而不是隐私参与方发生变化。当前 TUIC 路径上默认再承载 DoQ会形成 QUIC-over-QUIC，可能造成超时、拥塞控制和故障相关性增加，因此不作为默认配置。

ODoH 只有在 Proxy 与 Target 属于不同信任域、日志最小化且链路正确实现时，才能将用户来源与查询内容有效分离。

## 6. MASQUE 与隐私分区路线

单层 MASQUE 代理仍然可以看到客户端来源和目标，不能单独提供匿名性。其产品价值在于标准化 `CONNECT-UDP`/`CONNECT-IP`、HTTP 身份与错误语义，以及构建多跳结构的能力。

后续高隐私模式可以采用：

```text
Client -> Ingress Relay -> Egress Gateway -> Target
          知道来源          知道目标
          不解内层目标      不知道家庭来源
```

实现条件：

- Client 到 Egress 必须有 Relay 无法解密的内层保护；
- Relay 与 Egress 不应由同一日志体系关联；
- Egress 不接收用户名、邮箱、永久设备 ID 或家庭来源 IP；
- 配额使用短期、不含身份语义的令牌；
- DNS 路径也要避免重新把来源和查询汇聚到同一方；
- 两跳故障、延迟和成本必须可见，并能安全回退到用户明确选择的模式。

如果 Relay 与 Egress 在同一服务器或同一信任域中，结构上的两跳不构成实质隐私分区。

## 7. 元数据与流量分析限制

即便内容已加密，观察者仍可能分析：

- 连接起止时间；
- 上下行字节量与方向；
- 包长分布；
- 突发与空闲周期；
- 目标地址及共享基础设施特征；
- 客户端、TLS、QUIC 或 HTTP 指纹。

后续可研究尺寸分桶、DNS padding、低速受控 padding 和多用户汇聚，但这些措施会增加带宽、延迟和 CPU，并可能形成新的稳定指纹。默认模式不应开启大比例随机填充，也不应声称能抵抗全球观察者。

## 8. 内核优化与隐私的关系

内核优化主要改善性能、资源边界和抗滥用能力，并不会自动增加匿名性。

推荐用途：

- nftables/XDP 在早期丢弃明显畸形包和限制洪泛；
- `SO_REUSEPORT` 与可选 eBPF 保持同一会话进入同一 worker；
- GRO/GSO 和批量 I/O 减少每包成本；
- PMTU 与 pacing 减少分片和排队；
- CPU/IRQ 调度降低软中断争用；
- 有界 map、重组池和 session 速率防止资源耗尽。

不建议在 XDP/eBPF 中实现长期密钥处理、完整加密、FEC 或复杂用户策略。AF_XDP 仅适合经过硬件兼容性和基准验证的极限模式，不应在 ESXi、普通 OpenWrt 或 30 Mbps 服务端默认开启。

## 9. 多用户隐私与安全隔离

当前 Alpha 已使用 FEC V2 提供每设备独立密钥、并发会话状态和独立上游 socket，并拒绝重复认证序列。达到生产级多用户隔离还必须补充：

- 防重放窗口；
- 设备撤销和密钥轮换；
- 用户、设备和会话资源上限；
- 公平带宽调度；
- 无效认证速率限制；
- 目标日志默认关闭；
- 管理员也不能从界面读取长期密钥明文；
- Egress 不接收不必要的永久身份字段。

身份隔离是多用户安全的前提，不能用“多个 TUIC UUID”替代完整的数据面隔离。

## 10. 日志与数据保留

建议将日志分为认证事件、性能指标、安全事件和业务目标四类。默认策略：

- 不保存 URL、内容、完整域名或目标 IP 历史；
- 来源 IP 仅在必要安全窗口中短期保存，并支持截断或轮换哈希；
- session 使用随机内部 ID；
- 配对 Token 使用一次后删除；
- 诊断包先脱敏并展示清单；
- 遥测默认关闭；
- 管理员可查询数据保留期限并一键清理非必要数据。

运营部署如依法需要额外日志，应明确告知用户收集内容、目的、访问权限和保留期限，不能沿用“默认无日志”的描述。

## 11. 失败与降级策略

智能降级必须保持隐私语义，不应为了可用性静默降低安全等级：

- DoH 失败可回退 DoT，但不自动回退公网明文 DNS；
- WARP 故障是否回退 Direct 必须由管理员策略明确指定；
- 高隐私双跳故障时，不得静默降为单跳；应提示或按预先选择的策略处理；
- 证书验证失败不得自动关闭验证；
- UDP 受限时，未来的 HTTPS/TCP 回退仍须保持认证与加密；
- 配置或更新失败应回滚，不应留下部分开放端口或半生效规则。

## 12. 验证方法与对外声明

每项优势都应有可重复证据：

| 声明 | 必需证据 |
|---|---|
| 弱网恢复 | 不同随机/突发丢包下的有效吞吐、P95/P99 延迟和冗余开销对照 |
| 多出口容错 | 单/双 worker 故障、新旧连接行为和恢复观察测试 |
| 内核加速 | 同硬件同负载下 CPU、softirq、PPS、延迟和 drop 对照 |
| DNS 隐私 | 路由、抓包和泄漏测试；明确解析器可见信息 |
| 双跳隐私 | Relay/Egress 分别可见字段审计，确认无共享标识和日志关联 |
| 多用户隔离 | NAT 后多设备、并发 session、撤销、配额和资源耗尽测试 |

对外允许使用：

- “加密客户端到网关的传输”；
- “在配置冗余范围内恢复部分丢包”；
- “按新连接使用多个健康出口”；
- “默认最少日志和每设备独立凭据”（完成对应功能后）；
- “可选隐私分区模式”（完成双跳与审计后）。

对外不得使用：

- “完全匿名”；
- “运营商/GFW 无法识别”；
- “永不封锁”；
- “绝对不丢包”；
- “三路 WARP 带宽叠加三倍”；
- “DoQ 比 DoH 更隐私”；
- “单层 MASQUE 隐藏所有元数据”。

## 13. 阶段路线与启用策略

1. **第一版生产基础**：FEC V2、多用户会话隔离、批量 UDP、PMTU、Controller、Revision、Passwall/v2rayN 适配。
2. **条件加速**：GRO/GSO、reuseport、多 worker、受控 nftables/eBPF；自动检测和回滚。
3. **MASQUE 单跳实验**：建立标准基线，不宣传隐私分区。
4. **DoQ 实验**：只在适合的直达或专用路径测试，保留 DoH/DoT。
5. **双跳隐私与 ODoH**：不同信任域、短期令牌、分离日志，通过隐私审计后才开放。
6. **Extreme 数据面**：XDP/AF_XDP，仅在硬件和负载证明有收益时启用。

功能状态应在 CLI、UI 和发行说明中明确标记 `stable`、`candidate` 或 `experimental`，实验模块不得因“Auto”而自动进入生产链路。
